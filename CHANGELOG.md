# Changelog

All notable changes to TRANSFORM are recorded in this file.

The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/). Each change adds a line under **Unreleased**. When a version is released, its section is also summarized in `TRANSFORM.UsersGuide.ReleaseNotes`, the release-notes package inside the library, as the Modelica Standard Library does.

## [Unreleased]

### Changed

- `TRANSFORM/package.mo`: `main` carries `version="1.2.0-dev"` and adds `noneFromVersion="1.1.0"` to the conversion annotation, so models written for 1.1.0 load without conversion. The release date `versionDate` is removed until the next release.
- `TRANSFORM/package.mo` declares `SDF(version="0.4.5")` in its `uses` annotation. The critical heat flux and film boiling look-up tables (`Groeneveld2006LUT`, `Alphas_TwoPhase_3Region_CHFtransition`, the example `Groeneveld2001LUT_FilmBoilingCoefficient` and the examples of the first two) read their data with `SDF.NDTable`, but the library did not say so (#98). SDF is public under the BSD 2-Clause license. What to do: in Dymola 2026x, nothing; it ships SDF 0.4.6, which loads 0.4.5 models without conversion (older Dymola versions are unchecked). Other users install SDF 0.4.5 from [SDF-Modelica](https://github.com/ScientificDataFormat/SDF-Modelica/releases) or, in OpenModelica, with `installPackage(SDF, "0.4.5")`. Only the models that use these tables need SDF: OpenModelica 1.27.1 loads TRANSFORM without it and prints the install command. With SDF installed, these models also run in OpenModelica and match the Dymola results. `README.md` now lists ExternalMedia and SDF as optional libraries. Results are unchanged.

### Fixed

- `TRANSFORM.Math.linspace_2Dedge` and `TRANSFORM.Math.linspace_2Dcorner`: the loop that fills the interior is renamed from `i`/`j` to `iRow`/`jCol`. OpenModelica 1.27.1 inlines `linspace`, whose own iterator `i` then shadowed the loop's `i`. Depending on the sizes, interior values were wrong (`check_linspace_2D`: 3.125 instead of 2.5) or the simulation stopped with "Dimension 1 has bounds 1..5, got array subscript 6" (`Winding_12D` and the 2D conduction models, whose start temperatures use `linspace_2Dedge`). Dymola results are unchanged. In OpenModelica, `check_linspace_2D` now matches Dymola exactly, and `Winding_12D` and `Winding_12D_variableArea` simulate and match Dymola within 2e-4.
- Two examples used constructs the Modelica language does not allow, which Dymola accepts and OpenModelica rejects: `TRANSFORM.Fluid.Volumes.Examples.Condenser_Test` read `coolFlow.Medium.X_default` (a package constant reached through a component) and now leaves out that argument of `setState_pTX`, whose default is the medium's reference composition (the same value for water); `TRANSFORM.HeatAndMassTransfer.Examples.ExamplesFrom_NellisAndKlein.Figure_1_8_UniformThermalEnergyGeneration_Plane` took `sum(0)` of a scalar in a display-only check and now sums `wall.internalHeatModel.Q_flows ./ wall.Vs`, which is 0 here and follows the wall if heat generation is added. Values are the same; Dymola results are unchanged, and both now run in OpenModelica and match Dymola.

## [1.1.0] - 2026-11-03

### Added

- `CONTRIBUTING.md`: how to make changes without breaking user models (versions, renames, deprecations, removals) and how a release is made. A pull request template asks for tests, a changelog line and, for renames or removals, a run of the conversion guard in TRANSFORM-UnitTests.
- `CHANGELOG.md` and the `TRANSFORM.UsersGuide.ReleaseNotes` package, so that every change is recorded and each release is summarized inside the library.
- Regression tests for `TRANSFORM.Examples.MoltenSaltReactor.MSDR_noBOP` (15 signals) and the new standalone `TRANSFORM.Examples.MoltenSaltReactor.Components.Examples.DRACS_Test` (5 signals). Their baselines were recorded before the fixes for issues #111–#116.
- `TRANSFORM.Media.Interfaces.Fluids.PartialMedium` now has the function `massFraction`, which MSL 4.1.0 added to `Modelica.Media.Interfaces.PartialMedium`. `PartialPureSubstance` and `TableBased` implement it (`Xi := fill(0,0)`), so every TRANSFORM medium built on them has it. Without it, TRANSFORM fluid media were not subtypes of the Modelica.Fluid medium under MSL 4.1.0, and Dymola warned "Redeclaration requires a subtype ... missing public function massFraction" (an error in its pedantic check). This matters because Dymola 2026x ships only MSL 4.1.0. The change only adds the function; results are unchanged and user models need no change, unless your own medium extends one of these packages and already declares a `massFraction` of its own: then change that declaration to `redeclare function extends massFraction` or remove it. A new test, `TRANSFORM.Media.Examples.MassFraction_Test`, calls it on a table-based and a linear medium.

### Changed

- `TRANSFORM.Fluid.Volumes.Examples.ExpansionTank2_Test`: the outlet resistance `resistance.R` is 100 instead of 0.01. With 0.01 the tank took no water after its level settled, so no CO2 reached it and the tested tank concentration `expansionTank.C[1]` was solver noise (1e-11 to 1e-9). Now the tank is still filling when the CO2 arrives and `C[1]` rises to about 0.008. The level ends at 2.053 m instead of 2.043 m. Results of this example change.
- `TRANSFORM/package.mo` declares `version="1.1.0-dev"` and `conversion(noneFromVersion="0.5", noneFromVersion="1.0")`. The next release is 1.1.0; until then `main` carries the `-dev` version. Models written for 1.0 or 0.5, such as TRANSFORM-Training, need no change: Dymola loads them as before, and OpenModelica prints only a note that the library is compatible without conversion instead of warning that the versions differ. Versions have three parts from now on.
- `.gitignore` now tracks `TRANSFORM/Resources/Scripts/Conversion/`, the conventional home of Modelica conversion scripts. The rest of `TRANSFORM/Resources/Scripts/` stays ignored.
- `TRANSFORM.Nuclear.ReactorKinetics.Data`: new documentation explains what `C_nominal` does, that it matters only in tools that integrate the scaled trace inventories, and how to set per-species values in your own record. The 1e14 defaults are unchanged (#117). The `C_nominal` descriptions in the data records point to it. Text only.
- `README.md`: the section on checking that the library works points to TRANSFORM-UnitTests and DSTF instead of `runAll_*.mos` scripts, which no longer exist.

### Fixed

- `TRANSFORM/package.mo` declares `ExternalMedia(version="4.0.0")` in its `uses` annotation. The CoolProp media in `TRANSFORM.Media.ExternalMedia` and the supercritical CO2 examples already needed ExternalMedia, but the library did not say so (#106). ExternalMedia 4.0.0 is the release built on MSL 4.0.0; 4.1.x states that 4.0.0 models need no conversion. ExternalMedia stays optional: without it, TRANSFORM still loads in Dymola and OpenModelica (OpenModelica prints a notification with the `installPackage` command), and every model that does not use ExternalMedia works as before. Results are unchanged.
- `TRANSFORM.Utilities.Visualizers.IconColorMap_1D`: each element is colored from its own value `val[i]`; before, every element took the color of `val[1]`. The `dynColor` output changes for `n > 1`; nothing else does. No model in the library uses this block. A new test, `TRANSFORM.Utilities.Visualizers.Examples.IconColorMap_1D_Test`, checks it.
- `TRANSFORM.Media.Interfaces.Fluids.TableBased`: `MM_const` is declared as `SI.MolarMass` instead of the Modelica.Media `MolarMass` type, whose upper bound of 0.25 kg/mol was below the 0.252 kg/mol of `TableBasedTherminol66`. `PartialLinearFluid` and `PartialSimpleMedium_other` already used `SI.MolarMass`. No value changes; results are unchanged.
- `TRANSFORM.Examples.MoltenSaltReactor.Data.data_RCTR`: `rs_ring_cell` is now written as `{(i - 1)*length_reflA_ring_cell for i in 1:nARs + 1}` instead of being built from its own earlier elements, which Dymola's pedantic check rejects. The values are the same; results are unchanged.
- Array modifiers now use `each` where one value applies to every element, for example `nVs[2](each min=1)` or `Ts_start_1(each displayUnit="K")`. OpenModelica requires `each` and stopped with "possibly due to missing 'each'"; Dymola already assumed it, so results are unchanged. 188 modifiers in 77 classes changed, across `Fluid`, `HeatAndMassTransfer`, `Nuclear`, `Utilities` and `Examples`: declarations in base classes, geometry models, boundary conditions and records, and use sites in examples such as `SFR`, `CIET_nureth`, `NSSS`, `IRIS` and `GenericModule`. Nothing else in those lines changed.
- `TRANSFORM.Utilities.Visualizers.IconColorMap`, `IconColorMap_1D` and the tube colors of `TRANSFORM.HeatExchangers.GenericDistributed_HX`, `GenericDistributed_HX_Rwall` and `GenericDistributed_HX_withMass`: the color map is now held in a protected parameter `colorMapData_` before it is passed to `scalarToColor`. OpenModelica could not generate code for the old form, so every model with a fluid volume, pipe or tee failed to build there (#109). The colors are unchanged.
- `TRANSFORM.Examples.MoltenSaltReactor.MSDR_noBOP`: the drain-tank thimble convection area `surfaceAreas_thimble` passed to `DRACS` no longer multiplies by `DRACS.nP_outer_drainTank[1].nParallel`, which counted the 360 thimbles twice and made the heel-to-thimble conductance 360 times too large, on both the salt and gas sides (#112). `MSDR_noBOP` results change.
- `TRANSFORM.Examples.MoltenSaltReactor.Components.DRACS`: the water-tank make-up controller `PID_waterTank` is tuned to `k=200`, `Ti=300` instead of the `LimPID` defaults (`k=1`, `Ti=0.5`), which left the make-up flow in a barely damped oscillation of about 1 to 99 kg/s with a period of about 760 s (#113). `MSDR_noBOP` results change.
- `TRANSFORM.Examples.MoltenSaltReactor.Components.DRACS`: the NaK loop now circulates by natural convection. The downcomer `downcomer_DRACS` runs downward (`angle=-pi/2` instead of `+pi/2`, so the loop no longer climbs 36.6 m), and `resistance` has `R=1` instead of `R=-2000`, which acted as a pump (#111). The riser and downcomer each use `nV=10` volumes instead of 1, so the static-head regularization at the end of each leg no longer averages away the buoyancy head and reverses the loop (#116). `MSDR_noBOP` results change.
- `TRANSFORM.Examples.MoltenSaltReactor.Components.DRACS` and `MSDR_noBOP`: the four thimble walls start at the temperature of the fluid beside them instead of unrelated data temperatures, so there are no large heat-flow pulses at t=0 (up to 4.9 GW before) (#114). The inner walls start at the NaK start `0.5*(T_hot_dracs + T_cold_dracs)`, the outer water-tank wall at the tank start `0.5*(T_inlet_waterTank + T_outlet_waterTank)`, and in `MSDR_noBOP` the outer drain-tank wall at the heel start `data_PHX.T_inlet_tube`. All are expressions of existing parameters. Results change mainly during start-up; end values change by less than 2 %.
- `TRANSFORM.Examples.MoltenSaltReactor.Components.DRACS`: the water-tank thimble walls `thimble_outer_waterTank` and `thimble_inner_waterTank` use the water-tank thimble length `length_thimbles_waterTank` (25 ft), as their NaK pipe already did, instead of the drain-tank length (204 in). `radiation_waterTank` uses the water-tank wall areas instead of the drain-tank ones. Found while checking #111–#116. `MSDR_noBOP` results change: more heat reaches the water tanks, the NaK runs colder and the drain-tank heel ends about 6 K cooler.
- `TRANSFORM.Examples.MoltenSaltReactor.Components.DRACS`: the four NaK pipes (`thimbles_drainTank_fluid`, `riser_DRACS`, `thimbles_waterTank_fluid`, `downcomer_DRACS`) use `massDynamics=SteadyStateInitial`, so the tool computes consistent start pressures. With the default start pressures, which ignore the 18 m of hydrostatic head that the downward downcomer (#111) makes real, the loop flows at t=0 disagreed (riser −502 kg/s, downcomer +6630 kg/s) and settled within 5 ms. All loop flows now start near 130 kg/s; results after the first milliseconds change by less than 1 %.
- `TRANSFORM.Examples.MoltenSaltReactor.Components.DRACS`: the descriptions of `surfaceAreas_thimble` and `alphas_drainTank` now say element [1] is salt and [2] is gas (they said "gas and salt"). Text only.
- `TRANSFORM.Fluid.ClosureRelations.PressureLoss.Models.DistributedPipe_1D`: in `SinglePhase_Developed_2Region_NumStable`, `SinglePhase_ReynoldsRelation_NumStable`, `SinglePhase_Turbulent_MSL`, `TwoPhase_Developed_2Region_NumStable` and `TwoPhase_Developed_2Region_NumStable_alternate`, the homotopy `simplified` relation now uses `max(abs(dp_nominal), dp_small)` instead of `dp_nominal`, so pipes whose net height change is downward no longer get a negative conductance during homotopy initialization (#115). The `actual` relation and `dp_nominal` itself are unchanged.
- Graphics annotations use only standard attributes, so Dymola's pedantic check accepts them. On `Text`, the text color is `textColor` instead of `lineColor`, and the fill and line attributes that `Text` does not have (`fillColor`, `fillPattern`, `lineThickness`, `pattern`) are removed. Connection lines lose the `thickness` that had no value. 618 graphics records (537 `Text`, 81 `Line`) in 333 files, across the whole library. Annotations only: results are unchanged, and Dymola 2026x exports of every icon and diagram in those files are pixel-identical before and after.
